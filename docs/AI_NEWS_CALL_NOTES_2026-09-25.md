# Stavplus AI News Pipeline — заметки к созвону

Дата: 25.09.2026  
Контекст: PR #2 `feature/ai-news-pipeline`

## 1. Коротко: что мы хотим получить

Целевая схема:

```text
разрешённый источник
→ получение новости
→ извлечение исходного текста и фактов
→ AI-рерайт через OpenRouter
→ проверки
→ черновик News в Django
→ проверка редактором
→ публикация
```

Текущий PR уже реализует основу этой схемы, но **это ещё не система, которая может брать любую новость с любого сайта и автоматически её рерайтить**.

Главное ограничение текущей версии: она работает прежде всего с заранее согласованными **RSS/Atom-лентами**. Обычную HTML-страницу статьи текущая версия специально не скачивает и не парсит.

---

## 2. Что такое RSS

**RSS** — это специальная машинно-читаемая лента сайта, обычно в XML.

Упрощённо сайт публикует не только страницы для человека, но и ленту примерно такого содержания:

```xml
<item>
  <title>Заголовок новости</title>
  <link>https://example.ru/news/123</link>
  <description>Краткий текст новости...</description>
  <pubDate>...</pubDate>
</item>
```

Программе не нужно открывать сайт как браузер, искать блок с заголовком, рекламой и текстом. Она получает структурированные записи из ленты.

**Atom** — похожий формат лент. Для нашей задачи принципиальной разницы почти нет: текущий код умеет разбирать RSS и Atom.

### Почему RSS удобен

- структура предсказуемее HTML;
- меньше зависимость от дизайна сайта;
- не требуется браузер или JavaScript;
- меньше лишнего контента;
- проще дедупликация и автоматическая обработка;
- ниже техническая сложность MVP.

### Важное ограничение

Наличие публичной RSS-ленты **не означает автоматически**, что владелец разрешает копировать, перерабатывать и публиковать его материалы. Поэтому в коде предусмотрены отдельные признаки редакционного и юридического согласования источника.

---

## 3. Как текущая система работает

### Шаг 1. NewsSource

В Django создаётся разрешённый источник. Для него задаются:

- название;
- URL RSS/Atom;
- разрешённые домены;
- активность;
- редакционное согласование;
- юридическое согласование;
- проверка условий использования;
- проверка robots.txt;
- минимальный интервал запросов.

Миграция специально не добавляет автоматически ни одного разрешённого СМИ.

### Шаг 2. Ingest

Команда:

```bash
python manage.py ingest_external_news
```

загружает RSS/Atom и создаёт `ImportedNewsItem`.

Перед сохранением выполняются:

- проверка источника;
- проверка домена;
- robots.txt;
- ограничение размера ответа;
- нормализация текста;
- дедупликация по URL;
- дедупликация по SHA-256 содержимого;
- выделение кандидатов фактов.

### Шаг 3. AI-рерайт

Команда:

```bash
python manage.py rewrite_pending_news
```

передаёт материал в OpenRouter.

OpenRouter здесь — шлюз к выбранной языковой модели. Конкретная модель задаётся через:

```text
OPENROUTER_MODEL
OPENROUTER_FALLBACK_MODEL
```

То есть модель можно менять без переписывания всего pipeline.

Модель должна вернуть структурированный JSON:

- title;
- excerpt;
- content;
- category_suggestion;
- tags;
- meta_title;
- meta_description;
- source_facts;
- warnings.

### Шаг 4. Черновик

Результат проходит sanitization и сохраняется как `News`:

```text
editorial_status = draft
is_published = false
is_featured = false
```

Автоматическая публикация в v1 запрещена. Редактор должен проверить материал и опубликовать его вручную.

## 4. Почему сейчас нельзя сказать «берём главные СМИ РФ и всё работает»

Есть несколько разных проблем.

### Проблема A. Не у каждого сайта есть подходящая публичная RSS/Atom-лента

Текущий pipeline **не является универсальным HTML-парсером**.

Если у источника нет подходящей RSS/Atom-ленты, одной записи домена в `NewsSource` недостаточно.

#### Решения

1. Для MVP использовать источники с нормальными RSS/Atom.
2. Для остальных написать отдельные адаптеры официальных API.
3. Если это допустимо условиями источника — позже реализовать HTML extraction как отдельный контролируемый адаптер.
4. Не превращать один универсальный scraper в код, который пытается угадать структуру любого сайта.

Предпочтительная архитектура:

```text
Source
├── RSSAdapter
├── AtomAdapter
├── ApiAdapter
└── HtmlAdapter (только если действительно нужен)
```

---

### Проблема B. Техническая доступность ≠ разрешение на использование

Даже если RSS открыт без авторизации, это ещё не даёт автоматически право брать полный материал, делать AI-рерайт и публиковать его как новую статью.

Для коммерческих информагентств и СМИ условия могут существенно различаться.

#### Решение

Вести allowlist источников:

| Поле | Значение |
|---|---|
| Источник | название |
| Domain | разрешённый домен |
| Feed/API | конкретный endpoint |
| Тип | RSS / Atom / API |
| Terms checked | дата проверки |
| Robots checked | дата проверки |
| Editorial approved | да/нет |
| Legal approved | да/нет |
| Attribution | что указывать |
| Notes | ограничения |

Пока источник не согласован — `is_active=false` / approval flags выключены.

---

### Проблема C. AI нельзя считать источником фактов

Задача модели — **переформулировать предоставленные сведения**, а не дополнять новость собственными знаниями.

Текущий prompt это запрещает, однако одной инструкции модели недостаточно.

При review PR #2 обнаружена важная проблема: модель возвращает `fact_id`, `statement` и `source_url`. Код проверяет существование `fact_id` и URL, но сейчас недостаточно жёстко связывает возвращённый `statement` с исходным фактом.

Теоретически модель может сослаться на существующий `fact_id`, но сформулировать под ним неподтверждённое утверждение.

#### Решение

Источник истины должен находиться в приложении, а не в ответе модели.

Лучший вариант:

```text
fact-1 → исходный statement
fact-2 → исходный statement
fact-3 → исходный statement
```

Модель возвращает только ссылки на `fact_id`. Приложение самостоятельно восстанавливает соответствующие исходные факты.

Добавить regression test: forged statement под существующим `fact_id` должен быть отклонён.

---

### Проблема D. SSRF / безопасность загрузки внешних URL

Текущий код уже запрещает localhost, `.local`, прямые private/reserved IP и домены вне allowlist.

Но при review обнаружено, что hostname недостаточно проверить только как строку. Домен может резолвиться во внутренний IP, а redirect может попытаться отправить сервер на внутренний адрес.

#### Решение

Перед внешним соединением:

1. DNS-resolve hostname;
2. проверить все полученные IP;
3. разрешать только global addresses;
4. контролировать каждый redirect;
5. запрещать loopback/private/link-local/reserved;
6. добавить regression tests.

---

### Проблема E. Возможна параллельная обработка одной новости

Сейчас два одновременно запущенных worker/command потенциально могут увидеть один `PENDING` item до его перевода в `PROCESSING`.

Последствия:

- два обращения к модели;
- двойная стоимость;
- гонка при обновлении черновика.

#### Решение

Сделать атомарный claim записи перед обращением к OpenRouter, например через транзакцию и блокировку строки (`select_for_update` / подходящий механизм для PostgreSQL).

## 5. Почему лучше начинать с первоисточников

Для Stavplus логичнее сначала проверить официальные источники:

- органы власти;
- МЧС;
- МВД;
- министерства;
- прокуратуру;
- СК;
- Банк России;
- Правительство Ставропольского края;
- региональные ведомства.

Причина не в том, что их материалы автоматически свободны для любого использования — условия всё равно проверяются.

Преимущество информационное:

```text
ведомство → Stavplus
```

лучше, чем:

```text
ведомство → федеральное СМИ → Stavplus
```

Меньше промежуточных пересказов и проще контролировать происхождение факта.

## 6. Какой MVP предлагается обсудить на созвоне

Не делать сразу полностью автономного «AI-журналиста».

Предлагаемый v1:

```text
5–10 согласованных источников
→ RSS/API
→ ingest
→ дедупликация
→ AI-рерайт
→ проверки фактов
→ DRAFT
→ человек проверяет
→ публикация
```

После стабильной эксплуатации можно добавить:

- больше источников;
- отдельные API adapters;
- автоматическую классификацию по тематике/региону;
- фильтрацию нерелевантных материалов;
- похожесть/дедупликацию одной новости из разных источников;
- расписание;
- budget limits;
- мониторинг ошибок;
- при отдельном решении редакции — более высокий уровень автоматизации публикации.

## 7. Что нужно решить с тимлидом на созвоне

1. Какие источники нам реально нужны?
2. Только федеральные СМИ или также официальные первоисточники?
3. Нужен полный текст или достаточно данных RSS?
4. Какие источники юридически/редакционно разрешено использовать?
5. Обязательна ли ссылка/атрибуция первоисточника?
6. Нужен ли только черновик или в будущем требуется автопубликация?
7. Какой объём: 10, 50, 100+ материалов в сутки?
8. Какая модель OpenRouter будет использоваться?
9. Кто проверяет AI-материал перед публикацией?
10. Какие категории новостей автоматически отбрасывать?
11. Нужны ли отдельные адаптеры для сайтов без RSS?
12. Кто отвечает за список разрешённых источников и его актуальность?

## 8. Мои пометки / шпаргалка

**RSS** — XML-лента новостей сайта для программ.

**Atom** — аналог RSS.

**Feed** — сама RSS/Atom-лента.

**Endpoint** — конкретный URL, к которому обращается программа.

**API** — программный интерфейс сайта/сервиса. Обычно надёжнее HTML scraping, если владелец предоставляет официальный API.

**HTML scraping / parser** — программа скачивает обычную веб-страницу и извлекает из неё нужные элементы. Более хрупко: изменение вёрстки может сломать parser.

**OpenRouter** — сервис-посредник, через который приложение вызывает выбранную AI-модель.

**Prompt** — инструкция, которую приложение передаёт модели.

**Structured output** — модель должна вернуть не свободный текст, а JSON по заданной структуре.

**Fact candidate** — утверждение из исходного материала, которое система разрешает использовать как основание для рерайта.

**Deduplication** — защита от повторного импорта одной новости.

**SHA-256** — хеш содержимого; используется как один из способов определить дубликат.

**Allowlist** — список заранее разрешённых источников/доменов.

**robots.txt** — файл сайта с правилами для автоматических роботов. Это технический сигнал для crawler, а не лицензия на публикацию контента.

**SSRF** — класс серверной уязвимости, когда злоумышленник заставляет сервер обратиться по адресу, куда он обращаться не должен, например во внутреннюю сеть.

**DRAFT** — черновик, который не виден обычным посетителям сайта.

**Audit trail** — журнал действий: откуда пришёл материал, какой моделью обработан, какие были ошибки/предупреждения и кто опубликовал.

**Regression test** — тест, фиксирующий найденную ошибку, чтобы она не появилась снова после следующих изменений.

## 9. Текущий вывод

PR #2 — это уже основа безопасного AI news pipeline, но **не готовый универсальный агрегатор всех федеральных СМИ**.

До реального автоматического использования необходимо как минимум:

1. определить и проверить конкретные источники;
2. выбрать RSS/API для каждого;
3. согласовать правила использования;
4. закрыть найденную проблему привязки AI output к исходным фактам;
5. усилить SSRF protection;
6. исключить параллельную обработку одной записи;
7. прогнать pipeline на staging;
8. только после этого обсуждать расписание и дальнейшую автоматизацию.

Production этим документом и текущими PR не изменяется.
