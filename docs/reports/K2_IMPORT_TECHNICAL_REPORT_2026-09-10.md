## Изоляция источника и назначения

- Дамп K2 сохранён как сжатый SQL-архив и проверен через `gzip -t` и SHA-256.
- Архив K2 media объёмом около 31 ГБ также проверен через `gzip -t` и перенесён с контролем целостности.
- Источник поднят в отдельной MariaDB на `127.0.0.1:3307`; импортёр подключается к нему только на чтение.
- Целевая база — отдельный PostgreSQL тестового сайта.
- Перед операцией проверена страховочная копия целевой PostgreSQL-базы.
- Рабочий `stavplus.ru` не использовался как цель импорта и не изменялся.

## Архитектура импортёра

Импорт разделён на небольшие слои:

1. `source` читает категории, теги, связи и материалы из K2.
2. `domain` описывает переносимые сущности и результат обработки.
3. `transform` нормализует даты, статусы, текст, метаданные и slug.
4. `media` индексирует исходные каталоги, выбирает изображение и переносит файлы безопасным путём.
5. `service` оркестрирует импорт, транзакции, дедупликацию и отчётность.
6. Команда `import_k2` предоставляет режимы `--dry-run`, `--limit`, `--resume-from` и `--apply`.

`--dry-run` проходит тот же путь преобразования, но не изменяет PostgreSQL и каталог media. Боевой режим работает повторяемо: импорт можно безопасно перезапустить после остановки.

## Правила преобразования

- Вводный текст и основной текст K2 сохраняются раздельно без повторения лида.
- Legacy-даты переводятся в timezone-aware значения Django.
- Публикационные состояния K2 преобразуются в статусы Django.
- Категории и теги связываются через legacy ID; существующие одноимённые объекты принимаются импортёром вместо создания дубля.
- Конфликты slug разрешаются детерминированным суффиксом с legacy ID.
- Ограниченные поля обрезаются контролируемо с записью предупреждения в JSON-отчёт.
- Каждая новость обрабатывается в отдельной транзакции, поэтому ошибка одной записи не повреждает остальные.

## Перенос изображений

K2 хранит основные изображения по MD5 от строки `Image` + ID материала. Импортёр один раз строит индекс исходных файлов и затем выбирает лучший доступный размер в порядке `src → XL → L → generic`.

Файлы кладутся в content-addressed путь на основе SHA-256. Это устраняет повторное копирование одинаковых файлов и делает повторные запуски дешёвыми. Пути нормализуются, выход за разрешённые каталоги блокируется. В полном запуске найдено 24 444 основных изображения; 24 435 были скопированы в этом запуске, ещё 9 уже существовали после тестового импорта первых десяти записей.

## Обнаруженные проблемы и решения

| Проблема источника или первого запуска | Масштаб | Решение |
| --- | ---: | --- |
| Дублирующиеся названия категорий | 1 | Принятие существующей категории по точному имени с привязкой legacy ID |
| Дублирующиеся названия тегов | 1 | Аналогичное объединение по точному имени |
| Отсутствующие ссылки на теги | 163 | Материал импортируется, дефект источника фиксируется в JSON |
| Конфликты slug | 126 | Детерминированный суффикс legacy ID |
| Превышение длины метаполей | 2 | Контролируемое обрезание; ID `3332` и `17758` отмечены в отчёте |
| Отсутствующий inline-файл | 1 | Ссылка сохранена в отчёте: материал `23175`, `images/РО_Лога_3.jpg` |
| `IntegrityError` на категории и теге при пробном импорте | 2 | Исправлена логика повторного использования одноимённых объектов; повторный запуск дал 0 ошибок |
| Очень медленный поиск файлов | весь набор | Вместо повторного обхода 32 ГБ создан одноразовый индекс media |
| Потенциально опасный HTML из Joomla | системно | Добавлена очистка `script`, форм, обработчиков `on*`, `srcdoc` и опасных URL-схем |

## Безопасность и откат

- Пароли не попадают в командную строку и отчёты; настройки источника читаются из защищённого env-файла.
- Импортёр не выполняет запись в MariaDB.
- HTML очищается до публикации: удаляются исполняемые теги, событийные атрибуты и схемы `javascript:`, `data:` и `vbscript:`.
- Перед восстановлением и импортом создана и проверена резервная копия PostgreSQL.
- Повторяемость по `legacy_k2_id` позволяет исправлять трансформацию и запускать импорт заново без размножения записей.

## Остаточные ограничения

- 163 отсутствующие связи тегов и один inline-файл являются дефектами исходных данных, а не потерей при импорте.
- K2-комментарии, рейтинги, авторы, вложения, extra fields и отдельная сущность галерей не входили в текущий объём миграции.
- CKEditor 4 остаётся отдельным техническим долгом; замена редактора требует продуктового и лицензионного решения.
- Перед переключением домена нужен короткий smoke-тест через боевой Nginx и проверка нескольких материалов разных лет.
